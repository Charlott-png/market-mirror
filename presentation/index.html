04 · Architecture & Technical Approach

A layered system with clear responsibilities.

The architecture separates presentation, business rules, data, and AI services so each part can be tested and explained independently.

ExperienceHTML · CSS · JavaScriptResponsive pages, AJAX search, galleries, chat UI
→
ApplicationPython · FlaskRoutes, forms, permissions, checkout transactions
→
DataSQLAlchemy · SQLiteUsers, products, messages, carts, orders, history
Google Gemini APIVision + assistant
Security layerCSRF + auth + validation
FlaskJinjaSQLAlchemyFlask-LoginFlask-WTFPillowpytestGemini
Speaker NotesEstimated time: 1:30
  • 0:00–0:20 — Start at the browser layer: server-rendered HTML, one shared design system, and focused JavaScript enhancements such as AJAX search and chat polling.
  • 0:20–0:45 — Explain Flask’s role: routes receive requests, forms validate input, permissions decide access, and service functions execute business rules.
  • 0:45–1:05 — Explain the data layer: SQLAlchemy models relationships among users, listings, messages, carts, orders, images, and viewing history; SQLite supports the local class version.
  • 1:05–1:20 — Explain Gemini integration: images and bounded product facts are sent only when the relevant optional AI feature is enabled.
  • 1:20–1:30 — Close on separation of concerns: this structure made test-first development and future PostgreSQL deployment possible.
